- [x] Implement the native TypeScript Worker, D1 migrations, R2 persistence,

- [x] Disable legacy import while configured, retain local-only export/reset,

- [ ] Verify shared fixtures, idempotent remote replacement, limits, cache

## Verification gates

1. Worker typecheck, migrations, schemas, and Vitest/Miniflare tests pass.
2. Swift package tests cover record validation, replacement aggregation,
   recovery/crypto fixtures, and scheduling policy; the macOS Xcode target builds.
3. The Windows project compiles on a Windows .NET Framework 4.8 runner and its
   sync tests consume the same fixtures.
4. Applying the same response ten times does not change totals after the first
   application.
5. A one-device client runs for 48 hours without an ordinary sync request and
   exposes no enabled manual-sync action.
6. Hourly and UTC-day limits reject early/ninth accepted requests; all 429
   responses carry `Retry-After`.
7. Nonce, tag, AAD, device ID, and revision tampering fails authentication.
8. Logs and analytics contain no token, recovery code, ciphertext, key name,
   count, vault ID, or device ID.

## Local verification completed

- Worker schemas, OpenAPI, TypeScript, Wrangler types, fresh D1 migrations, and
  22 Worker tests pass.
- The macOS Swift package passes 54 tests and the real KeyStats Xcode target
  builds without code signing.
- Top-level, generated staging, and generated production Wrangler configurations
  pass dry-run packaging. Placeholder resource IDs remain intentionally
  non-deployable until CI injects the configured GitHub Environment values.
- Windows protocol, crypto, cache, scheduling, batching, and fixture tests are
  wired into a `windows-latest` .NET Framework 4.8 workflow. A Windows runner is
  still required for the authoritative compile and test result.
- Bootstrap archives are uploaded in at most 16-record pages and capped at 256
  exempt pages. The final accepted upload is persisted before cursor history is
  fetched, so an interrupted history pull resumes without re-uploading data.
- Current-record rollover first archives the exact prior envelope stored by the
  Worker, so a full 16-record offline backlog cannot deadlock on a missing prior
  day. A single-device 409 carries the authoritative count and both desktop
  clients persist it to stop ordinary scheduling.
- Daily cleanup prioritizes tombstoned vaults and uses a conservative
  800-operation ceiling. Large R2 deletion/orphan backlogs resume via bounded
  later runs instead of risking the Worker subrequest limit.
- Vault deletion stores a 30-day hash-only receipt in the tombstone transaction,
  so an initiating token can receive the lost `204` again even after physical
  vault deletion. Expired receipts are removed in bounded 100-row Cron pages.
- Client-generated bound tokens make vault creation and recovery replay-safe.
  Recovery and pairing can rotate an existing identity without duplicating its
  current/history contribution; read-only `/v1/state` returns accepted current
  revisions before the repaired client uploads. Valid recovery at the
  five-device limit returns only the vault ID and encrypted device descriptors
  for an explicit takeover choice.

Production deployment is not part of local implementation or verification; it
requires the configured GitHub Environment approval and Cloudflare secrets.
